# experiments — 진단용, 제품 경로 아님

VGGT 깊이맵으로 메쉬를 직접 만들 수 있는지 확인하려고 짠 도구들이다.
**결론은 "안 된다"였고**, 그 근거를 재현할 수 있게 남겨둔다.

상위 폴더의 `server.py` 를 import 하므로 VGGT 가 GPU 에 올라간다(약 50초).
어디서 실행해도 상위 폴더를 찾도록 경로를 넣어뒀다.

| 파일 | 하는 일 | 결과 |
|---|---|---|
| `vggt_tsdf_mesh.py` | VGGT 깊이맵 → TSDF 융합 → 메쉬 | 모터가 아니라 구겨진 판이 나왔다 |
| `vggt_align.py` | COLMAP sparse 점으로 프레임별 깊이 스케일 보정 후 잔차 측정 (융합 안 함) | 게이트 불통과 |
| `vggt_align_diag.py` | 보정 실패 원인을 반경/프레임편향/내부산포로 분해 | 원인 확정 |
| `gof_ba.py` | VGGT 포즈를 COLMAP 번들조정으로 다듬기 | 포즈가 오히려 나빠졌다 |

## 핵심 측정 (0831_2058 모터, 114장)

프레임마다 `d_colmap ≈ a·d_vggt + b` 를 적합한 뒤:

| | 잔차 중앙 | 절단 대비 | p90 | 절단 대비 |
|---|---|---|---|---|
| 스케일만 | 0.107 | 0.9배 | 0.430 | **3.6배** |
| 어파인 | 0.084 | 0.7배 | 0.371 | **3.1배** |

- p90 이 TSDF 절단거리 안에 드는 프레임: **110개 중 2개**
- **프레임 내부** 산포 p90 = 절단의 **3.13배** — `a`·`b` 는 프레임 전체에 같은 값을
  곱하고 더할 뿐이라 원리상 못 고친다
- 반경과의 상관 +0.120 — 접시 왜곡이 주범은 아니다
- 이 비교에는 VGGT 포즈가 안 들어간다 → 포즈 무죄
- VGGT 예측 초점거리 / COLMAP = 1.0058 → 광선 정합 문제 아님

**결론: VGGT 깊이맵 자체가 픽셀 단위로 실제 형상과 어긋난다.** 스케일·오프셋·포즈
어느 쪽을 고쳐도 해결되지 않는다. 그래서 제품 경로(`scan_run.py`)는 VGGT 를
점군 미리보기에만 쓰고, 형상이 필요하면 COLMAP 이나 가우시안을 거친다.
